# Проблемные места текущей архитектуры

- Устаревшая DWH на базе Microsoft SQL-сервера 2008 года.
- Все взаимодействие происходит через "старую" интеграционную шину, что создает единую точку отказа всей системы
- Невозможность формирования отчетов пользователями системы
- Долгая генерация отчетов
- Отсутствие масштабирования
- Наличие легаси систем
- Отсутствие регламентированного хранения и преобразования данных
- Отсутствие логирования и метрик


# Приоритеты (MoSCoW)

| Категория | Задача | Пояснение |
|:-|:-|:-|
|Must Have|Убрать шину как единую точку взаимодействия|Старая шина может стать причиной остановки всей системы что повлечет финансовые потери и репутационные риски|
|Must Have|Развернуть корректную ифраструктуру DataLakeHouse|Текущий механизм хранения данных неструктурирован и неорганизован, что замедляет time-to-market, а также замедляет процесс форЭто одна из ключевых задач системы.|
|Should Have|Настроить логирование и сбор метрик|Без логирования и метрик трудно определить узкие места и причины сбоев|
|Could Have|Трансформация накопленых данных под новый формат| Петабайты накопленых данных хранятся в неструктурированном виде. Для упрощения и унификации взаимодействия их можно перегнать в новый формат с помощью задач в Apache Airflow|
|Could Have|Настройка автоматического масштабирования|Принесет определенную пользу, но есть более приорететные задачи, которые надо успеть втечение года|
|Won't Have|Быстрое формирование всех отчетов|Хотя можно ускорить определенное количество отчетов, все их ускорить не получится в силу объема данных и сложности запросов к данным. А ускорение вертикальным масштабированием будет иметь ужасное соотношение cost/befit|
